# Code Implementation Agent Workflow (`/code-issue`)

This skill acts as a developer agent responsible for implementing features from GitHub project board issues. It picks up the next issue with status "Todo" and label "to-implement", executes the implementation using the Speckit workflow, and transitions the issue by updating its labels to "implemented".

---

## Target Project Board Context

- **Board URL**: `https://github.com/users/sebastienferry/projects/3`
- **Owner**: `sebastienferry`
- **Project Number**: `3`

---

## Workflow Steps

### Step 1: Check Prerequisites & Authentication

1. **Verify GitHub CLI Authentication**:
   Ensure `gh` CLI has project access permissions:
   ```bash
   gh auth status
   ```
   *If scope error occurs (`missing required scopes [read:project]`), prompt the user to run:*
   ```bash
   gh auth refresh -s project,read:project,write:project
   ```

2. **Verify Current Branch**:
   Ensure we're on the main branch to start implementation:
   ```bash
   git checkout main
   git pull origin main
   ```

---

### Step 2: Query & Pick Next Issue from Project Board

1. **Fetch Project Items**:
   Query items from Project Board 3:
   ```bash
   gh project item-list 3 --owner sebastienferry --format json
   ```

2. **Filter and Select Target Issue**:
   - Filter items matching `status == "Todo"` AND having label `"to-implement"`
   - Select the **first matching item** (oldest first)
   - Extract: `ISSUE_NUM`, `ISSUE_TITLE`, `ISSUE_BODY`, `ISSUE_LABELS`, `ITEM_ID`, and `NODE_ID`

3. **Fallback (if project CLI fails)**:
   Query repository open issues filtered by label:
   ```bash
   gh issue list --owner sebastienferry --repo fretly --state open --json number,title,body,labels,projectItems
   ```
   - Filter issues with label `"to-implement"` and project board status `"Todo"`
   - Select the first matching issue

---

### Step 3: Verify Specification Exists

1. **Check for Existing Specification**:
   - Look for spec directory matching the issue: `specs/<NNN-feature-name>/spec.md`
   - If not found, warn user: "No specification found for issue #<ISSUE_NUM>. Run `/specify-issue` first."
   - Optionally, check for `plan.md` and `tasks.md` in the spec directory

2. **Load Specification Context**:
   - Read the spec file to understand requirements
   - Extract key information: feature name, requirements, success criteria

---

### Step 4: Create or Switch to Feature Branch

1. **Check if Feature Branch Exists**:
   ```bash
   git branch -a | grep <ISSUE_NUM>-<short-name>
   ```

2. **Create or Switch to Branch**:
   - If branch exists: `git checkout <branch-name>`
   - If branch doesn't exist: `git checkout -b <ISSUE_NUM>-<short-name>`
   - Pull latest changes if branch already exists remotely

---

### Step 5: Execute Speckit Implementation

1. **Run Speckit Implement**:
   ```bash
   /speckit-implement
   ```
   *Executes all tasks sequentially from `tasks.md`, creating/updating models, renderers, components, and tests.*

2. **Handle Implementation Errors**:
   - If `/speckit-implement` fails, report the specific error
   - Suggest running `/speckit-tasks` to regenerate tasks if needed
   - Provide option to continue with manual implementation

---

### Step 6: Run Automated Verification

1. **Build Verification**:
   ```bash
   npm run build
   ```

2. **Linting**:
   ```bash
   npm run lint
   ```

3. **Testing**:
   ```bash
   npm test
   ```

4. **Handle Verification Failures**:
   - If any step fails, report the specific error
   - Provide guidance on how to fix common issues
   - Allow user to retry or continue with warnings

---

### Step 7: Transition Issue Labels

1. **Remove "specified" Label**:
   ```bash
   gh issue edit <ISSUE_NUM> --remove-label "specified"
   ```

2. **Add "validate" Label**:
   ```bash
   gh issue edit <ISSUE_NUM> --add-label "validate"
   ```

3. **Upon User Validation & Approval**:
   - Remove `validate` label and add `validated` label:
   ```bash
   gh issue edit <ISSUE_NUM> --remove-label "validate" --add-label "validated"
   ```
   - Update status to `Done` column on GitHub Project Board 3:
   ```bash
   gh project item-edit --id "<ITEM_ID>" --project-id 3 --field-id "<STATUS_FIELD_ID>" --single-select-option-id "<DONE_OPTION_ID>"
   ```

---

### Step 8: Commit and Push Implementation

1. **Stage All Changes**:
   ```bash
   git add .
   ```

2. **Commit Implementation**:
   ```bash
   git commit -m "feat/fix(<ISSUE_NUM>): implement <ISSUE_TITLE>
   
   - [Description of changes]
   - [Any breaking changes]
   
   Generated by Mistral Vibe.
   Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
   ```

3. **Push to Remote**:
   ```bash
   git push origin <BRANCH_NAME>
   ```

---

### Step 9: Create Pull Request

1. **Create PR for Review**:
   ```bash
   /create-pr
   ```
   *This will create a PR with proper title, description linking to the issue, and reviewers*

---

### Step 10: Update Changelog

1. **Open CHANGELOG.md**:
   Add entry under the `## [Next]` section:
   - For features: Under `### Added` -> `- <ISSUE_TITLE> (#<ISSUE_NUM>)`
   - For bug fixes: Under `### Fixed` -> `- <ISSUE_TITLE> (#<ISSUE_NUM>)`

2. **Commit Changelog**:
   ```bash
   git add CHANGELOG.md
   git commit -m "docs(changelog): update CHANGELOG.md for issue #<ISSUE_NUM>"
   git push origin <BRANCH_NAME>
   ```

---

## Error Handling

1. **No Issues Found**:
   - If no issues with status "Todo" and label "to-implement" are found, report:
     > "No issues found with status 'Todo' and label 'to-implement' in project board 3."
   - Suggest checking the board manually or running `/specify-issue` first

2. **No Specification Found**:
   - If no spec directory is found for the issue, report:
     > "No specification found for issue #<ISSUE_NUM>. Please run `/specify-issue` first to create the specification."

3. **Implementation Failed**:
   - If `/speckit-implement` fails, provide detailed error information
   - Suggest checking the `tasks.md` file for manual implementation steps

4. **Verification Failed**:
   - If build/lint/test fails, report which step failed and provide the error output
   - Allow user to fix issues and retry

---

## Output

The skill should output:
- **Issue Selected**: Issue number and title
- **Specification Found**: Path to the spec directory (or warning if not found)
- **Branch Used**: Name of the feature branch
- **Implementation Status**: Success/failure of speckit-implement
- **Verification Status**: Results of build, lint, test
- **Labels Updated**: Confirmation of label transitions
- **Pull Request**: PR number and URL (if created)
- **Next Steps**: Any remaining actions for the user

## Workflow Integration

This agent is designed to work seamlessly with the other agents:

1. **After `/spec-issue`**: Issues with "to-implement" label are ready for this agent
2. **Before `/pick-issue`**: This agent can be used as a standalone implementation agent
3. **With `/create-pr`**: Automatically creates PRs for implemented features

The complete workflow:
```
/spec-issue    → Creates spec, transitions "to-specify" → "to-implement"
/code-issue    → Implements code, transitions "to-implement" → "implemented"
```

---

## Notes

- This agent focuses only on implementation, assuming specifications already exist
- It works as a developer agent, executing the technical implementation
- The agent transitions issues from "to-implement" to "implemented" to mark completion
- All implementations are done in dedicated feature branches
- Automated verification ensures code quality before PR creation
