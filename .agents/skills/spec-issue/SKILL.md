# Specification Agent Workflow (`/spec-issue`)

This skill acts as a product owner agent responsible for creating specifications from GitHub project board issues. It picks up the next issue with status "Todo" and label "to-specify", creates a specification using the Speckit workflow, and transitions the issue by updating its labels.

---

## Target Project Board Context

- **Board URL**: `https://github.com/users/sebastienferry/projects/3`
- **Owner**: `sebastienferry`
- **Project Number**: `3`

---

## Workflow Steps

### Step 1: Check Prerequisites & Authentication

1. **Verify GitHub CLI Authentication**:
   Ensure `gh` CLI has project access permissions:
   ```bash
   gh auth status
   ```
   *If scope error occurs (`missing required scopes [read:project]`), prompt the user to run:*
   ```bash
   gh auth refresh -s project,read:project,write:project
   ```

2. **Verify Current Branch**:
   Ensure we're on the `main` branch to create specifications:
   ```bash
   git checkout main
   git pull origin main
   ```

---

### Step 2: Query & Pick Next Issue from Project Board

1. **Fetch Project Items**:
   Query items from Project Board 3:
   ```bash
   gh project item-list 3 --owner sebastienferry --format json
   ```

2. **Filter and Select Target Issue**:
   - Filter items matching `status == "Todo"` AND having label `"to-specify"` OR `"clarified"`
   - Select the **first matching item** (oldest first)
   - Extract: `ISSUE_NUM`, `ISSUE_TITLE`, `ISSUE_BODY`, `ISSUE_LABELS`, `ITEM_ID`, and `NODE_ID`

3. **Fallback (if project CLI fails)**:
   Query repository open issues filtered by label:
   ```bash
   gh issue list --owner sebastienferry --repo fretly --state open --json number,title,body,labels,projectItems
   ```
   - Filter issues with label `"to-specify"` OR `"clarified"` and project board status `"Todo"`
   - Select the first matching issue

---

### Step 3: Create Specification Using Speckit

1. **Create Feature Branch from main**:
   ```bash
   /speckit-git-feature
   ```
   This creates a new feature branch for the specification work.

2. **Run Speckit Specify**:
   ```bash
   /speckit-specify <ISSUE_TITLE>: <ISSUE_BODY>
   ```
   *Generates `specs/<NNN-feature-name>/spec.md` and related design artifacts.*

3. **Run Speckit Plan** (optional, can be done later):
   ```bash
   /speckit-plan
   ```
   *Generates `plan.md`, `research.md`, `data-model.md`, `quickstart.md`.*

4. **Run Speckit Tasks** (optional, can be done later):
   ```bash
   /speckit-tasks
   ```
   *Generates dependency-ordered `tasks.md` checklist.*

---

### Step 4: Transition Issue Labels

1. **Handle "clarified" Label**:
   - If the issue has "clarified" label, remove it:
   ```bash
   gh issue edit <ISSUE_NUM> --remove-label "clarified"
   ```

2. **Add "to-implement" Label**:
   ```bash
   gh issue edit <ISSUE_NUM> --add-label "to-implement"
   ```

3. **Remove "to-specify" Label**:
   ```bash
   gh issue edit <ISSUE_NUM> --remove-label "to-specify"
   ```

4. **Update Project Board Status** (if ITEM_ID available):
   Update status from `Todo` to `In Progress`:
   ```bash
   gh project item-edit --id "<ITEM_ID>" --project-id 3 --field-id "<STATUS_FIELD_ID>" --single-select-option-id "<IN_PROGRESS_OPTION_ID>"
   ```

---

### Step 5: Commit and Push Specification

1. **Commit Specification Files**:
   ```bash
   git add specs/<NNN-feature-name>/
   git commit -m "docs(spec): add specification for <ISSUE_TITLE> (#<ISSUE_NUM>)
   
   Generated by Mistral Vibe.
   Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
   ```

2. **Push to Remote**:
   ```bash
   git push origin <BRANCH_NAME>
   ```

---

### Step 6: Create Pull Request (Optional)

If the specification is ready for review:
```bash
/create-pr
```

---

## Error Handling

1. **No Issues Found**:
   - If no issues with status "Todo" and label "to-specify" or "clarified" are found, report:
     > "No issues found with status 'Todo' and label 'to-specify' or 'clarified' in project board 3."
   - Suggest checking for issues with "to-clarify" label that might need clarification first
   - Suggest running `/clarify-issue` to start the clarification process

2. **Authentication Failed**:
   - If `gh` CLI authentication fails, prompt user to run:
     ```bash
     gh auth login
     gh auth refresh -s project,read:project,write:project
     ```

3. **Git Operations Failed**:
   - If git operations fail, ensure we're in a valid git repository and the main branch exists.

---

## Output

The skill should output:
- **Issue Selected**: Issue number and title
- **Specification Created**: Path to the generated spec directory
- **Branch Created**: Name of the feature branch
- **Labels Updated**: Confirmation of label transitions
- **Next Steps**: Suggestions for what to do next (e.g., run `/speckit-plan` or `/speckit-tasks`)

---

## Notes

- This agent focuses only on specification creation, not implementation
- It works as a product owner, creating clear specifications for developers
- The agent transitions issues from "to-specify"/"clarified" to "to-implement" to hand off to development agents
- All specifications are created from the main branch to ensure clean starting points
- The agent supports the clarification workflow: issues with "clarified" label are processed the same as "to-specify"
